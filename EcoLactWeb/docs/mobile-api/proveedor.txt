Perfecto. Para **Proveedor** el criterio cambia bastante respecto al Administrador: aquí no necesitamos “gestionar el sistema”, sino permitir que el proveedor **consulte rápidamente qué entregó, qué calidad obtuvo, cuánto le corresponde cobrar y qué comunicaciones tiene**.

Como en tu sistema el Proveedor es principalmente un rol de consulta, la app debe ser todavía más simple.

## Estructura principal del rol PROVEEDOR

Yo la dejaría con solo **4 opciones inferiores**:

```text
INICIO · ENTREGAS · PAGOS · MÁS
```

Y globalmente arriba:

```text
🔔 Notificaciones
● Online / Offline
👤 Perfil
```

No pondría “Calidad”, “Liquidaciones”, “Compras” y “Comunicados” todos como botones inferiores porque terminaríamos llenando demasiado la navegación.

---

# 1. INICIO — Resumen personal

La pantalla inicial debe responder:

> **“¿Cómo van mis entregas y mis pagos?”**

No necesitamos gráficos administrativos.

### Cabecera

```text
Buenos días, Juan

● En línea                       🔔
Zona Huata
```

Si está sin internet:

```text
● Sin conexión
Mostrando datos guardados
```

---

### Resumen principal

Solo información útil para el proveedor:

```text
┌─────────────────┐ ┌─────────────────┐
│ 🥛 128.5 L      │ │ 🚚 4 entregas  │
│ Esta semana     │ │ Esta semana     │
└─────────────────┘ └─────────────────┘

┌─────────────────┐ ┌─────────────────┐
│ ✅ 3 aceptadas  │ │ 💰 S/ 186.40   │
│ Calidad         │ │ Por cobrar      │
└─────────────────┘ └─────────────────┘
```

No pondría estadísticas históricas complejas.

# 2. ENTREGAS

Este será uno de sus módulos principales.

El proveedor **no registra ni modifica entregas**.

Solo consulta.

```text
MIS ENTREGAS

[ Semana ] [ Mes ] [ Todo ]

🔍 Buscar / filtrar
```

Cada entrega como tarjeta:

```text
13 SEP · 08:42

32.5 L

Zona Huata
Registrado por: Carlos Mamani

🟢 Analizada

Resultado:
ACEPTADA                             >
```

Otra:

```text
12 SEP · 09:16

28 L

🟡 Pendiente de análisis             >
```

No usaría tablas en móvil.

# 4. CALIDAD

Aquí haría algo diferente al diseño web.

En móvil **no pondría Calidad como opción del menú inferior**, porque el proveedor normalmente llega al análisis desde una entrega.

Pero dentro de:

```text
Más → Mi calidad
```

sí puede consultar todos sus análisis.

Pantalla:

```text
MI CALIDAD

[ Todo ] [ Aceptadas ] [ Observadas ] [ Rechazadas ]

Este mes

✅ 12 aceptadas
🟠 2 observadas
🔴 1 rechazada
```

Luego:

```text
13 Sep
32.5 L
✅ ACEPTADA                              >

10 Sep
30 L
🟠 OBSERVADA                             >
```

Esto sirve para que detecte si tiene problemas repetitivos.

# 5. PAGOS

Este sería el tercer módulo principal de la barra inferior.

Yo agruparía aquí:

> “Entregué leche → se calculó cuánto me corresponde → me pagaron.”

No debería tener que entender la estructura interna del sistema.

# 12. Comportamiento offline del Proveedor

Aquí el diseño debe ser muy sencillo.

El proveedor puede consultar los datos previamente sincronizados:

```text
● Sin conexión
Mostrando información guardada

Última actualización
Hoy · 08:15 a. m.
```

Puede ver:

* QR;
* entregas descargadas;
* análisis descargados;
* liquidaciones;
* pagos;
* comunicados ya sincronizados.

Pero no debería aparecer información como si fuera actual cuando no lo es.

Por ejemplo:

```text
Datos actualizados hasta
13 Sep · 08:15 a. m.
```

Eso evita confusión.

# Estructura final del PROVEEDOR

La dejaría oficialmente así:

```text
PROVEEDOR
│
├── INICIO
│   ├── Resumen semanal
│   ├── Última entrega
│   ├── Liquidación actual
│   └── Comunicados importantes
│
├── ENTREGAS
│   ├── Mis entregas
│   └── Detalle de entrega
│       └── Resultado de calidad
│
├── PAGOS
│   ├── Resumen
│   ├── Liquidación actual
│   ├── Historial
│   └── Detalle de liquidación/pago
│
└── MÁS
    ├── Mi calidad
    ├── Comunicados
    ├── Mis compras
    ├── Notificaciones
    ├── Mi QR
    └── Mi perfil
```

### Navegación inferior definitiva

```text
┌────────┬──────────┬────────┬───────┐
│ Inicio │ Entregas │ Pagos  │  Más  │
└────────┴──────────┴────────┴───────┘
```

Este rol queda mucho más sencillo que Administrador, y eso es correcto: **el proveedor no necesita “administrar EcoLact”; necesita entender claramente qué entregó, qué calidad obtuvo y cuánto recibió o va a recibir**. Esa debería ser la lógica central de toda su experiencia móvil.

---
NOTA DE LA IMPLEMENTACIÓN REAL (ver proveedor.md en esta misma carpeta):
- Editar teléfono en "Mi Perfil" (sección 11) NO está soportado todavía — el endpoint es solo lectura, ni siquiera el panel web lo permite hoy. No lo actives en el diseño.
- El QR (sección 8) es real y funciona de punta a punta: el backend entrega el qr_token como texto, la app lo dibuja como imagen QR, y el Acopiador lo escanea para identificar al proveedor. Ver proveedor.md y acopiador.md para el contrato exacto y las librerías recomendadas (ZXing/ML Kit).
- El pago que recibe el proveedor (sección 5-6) siempre es en efectivo — no hay forma_pago variable ahí.
